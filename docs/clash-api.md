# Clash REST 与 WebSocket API

## 本地控制器

LucX 提供供 zashboard 等面板使用的 Clash 兼容接口，不是完整的 Mihomo API。控制器仅监听 `127.0.0.1`，设置入口为**设置 → 面板**。

| 设置 | 当前行为 |
| --- | --- |
| 启用控制器 | 默认关闭；开启后随服务启动。 |
| 端口 | 默认 `9090`；界面接受 `1024–65535`。 |
| 密钥 | 首次读取生成 UUID；提供生成和复制按钮。 |
| 面板日志级别 | 独立保存，默认 `error`，不改变 App 保存级别。 |

服务启动中或运行中修改开关、端口或密钥，只重启控制器监听器，不重载 Xray 或中断业务连接；已有面板连接需要重新连接。服务停止时只保存设置，供下次启动使用。控制器在首轮代理组测活之前启动；核心就绪与各节点测量结果分别表示各自状态，不需要等所有 URL-test 测量完成才开放 API。服务停止时监听器也关闭。

## 内置 zashboard

APK 内含 **zashboard v3.30.0** 的页面资源，无需外部托管网页。

1. 开启控制器，启动服务并等待连接成功。
2. 选择**打开内置 zashboard**，浏览器打开 `http://127.0.0.1:<port>/ui/`，默认是 `http://127.0.0.1:9090/ui/`。
3. App 通过浏览器片段 `#/setup?...` 传入后端地址、端口和密钥；这些设置不放在页面请求的查询参数中。

手动输入本地网址时，首次需在面板填写后端 `http://127.0.0.1:<port>`，并粘贴从 App 面板页复制的密钥。修改端口或密钥后，从 App 重新打开或更新已保存的后端。

HTML、脚本和样式可离线加载，但本地页面仍由运行中的控制器提供。实时统计和控制还需要服务及核心运行；离线页面不意味着代理流量、订阅更新或外部查询能在断网时工作。

## 鉴权与静态资源

- `GET`／`HEAD /ui/` 及其静态资源不需要 API 密钥；`/` 和 `/ui` 重定向到 `/ui/`。静态页面公开不代表控制接口公开。
- HTTP API 使用 `Authorization: Bearer <secret>`；也接受 `?token=<secret>`，WebSocket 可使用此参数。
- HTTP 鉴权失败返回 `401`。WebSocket 在协议升级后校验，失败时以 `NormalClosure` 关闭，不发送业务数据。
- `OPTIONS` 预检不需要密钥，返回 CORS 允许标头。

## HTTP 接口

### 基础与设置

| 接口 | 用途 |
| --- | --- |
| `GET /version` | API 适配层版本、Xray 核心标识及连接统计范围。 |
| `GET /configs` | 入站端口、`rule`／`global`／`direct` 模式及面板日志级别等基础信息。 |
| `PUT /configs`、`PATCH /configs` | 接受 `mode` 和 `log-level`；不是完整配置导入接口。 |

例如 `{"mode":"global"}` 保存模式并通过 Xray 路由 API 应用。`log-level` 只改变面板筛选级别，不触发核心重载。`silent` 对应不输出日志；显式 `/logs?level=...` 优先于面板保存级别。

### 代理组与节点

| 接口 | 用途 |
| --- | --- |
| `GET /proxies` | 全部代理组、物理节点及内置 `GLOBAL`、`DIRECT`、`REJECT`。 |
| `GET /proxies/{name}` | 指定目标详情，包括组的 `all`、`now` 和测量 `history`。 |
| `PUT /proxies/{name}` | 以 `{"name":"成员名称"}` 选择该组已有成员。 |
| `DELETE /proxies/{name}` | 清除组的临时运行选择。 |
| `GET /proxies/{name}/delay` | 单目标延迟；接受 `url`、`timeout`（毫秒），成功返回 `{"delay":ms}`，失败或超时返回 `504`。 |
| `GET /group`、`GET /group/{name}` | 代理组列表或详情。 |
| `GET /group/{name}/delay` | 测量组成员，返回名称到延迟的映射；未测通的值为 `0`。 |

`GLOBAL` 只接受工作区组作为默认组。手选组保存成员选择，自动组的手选只影响当前运行会话。`DIRECT` 对应 `direct`，`REJECT` 对应 `block`。它们不依赖用户分组，也不是可编辑的路由别名。

API 名称由 `ClashTagMapper` 去重。同名节点通常追加 ` (Node)`，继续冲突时追加编号；组名冲突也会加组编号。请求应使用 `/proxies` 返回的名称。原生规则仍直接使用工作区的组名或节点名，内置目标优先，组名优先于同名节点。

延迟是一次代理 HTTP HEAD 交换的耗时，包含连接准备和接收响应头，反映指定测活网址的可达性。测量走独立连接池和 `targetStrategy: AsIs` 出站，业务出站保留节点保存的解析策略。原生代理页、分组测量与订阅测活共用测量入口。

### 订阅提供者

| 接口 | 用途 |
| --- | --- |
| `GET /providers/proxies` | 列出订阅组提供者。 |
| `GET /providers/proxies/{name}` | 指定订阅组及其节点。 |
| `PUT /providers/proxies/{name}` | 通过与配置页相同的 `SubscriptionService` 更新订阅节点。 |
| `GET /providers/proxies/{name}/healthcheck` | 测量订阅组所属节点。 |
| `GET /providers/proxies/{name}/{node}/healthcheck` | 测量指定订阅节点。 |
| `GET /providers/rules` | 当前返回空提供者对象；`.dat` 由 App 的规则资源页管理。 |

订阅保存成功返回 `204`；部分跳过的原因写入日志。下载错误保留对应 HTTP 错误状态，网络失败返回 `502`，转换后没有有效节点返回 `422`，不以空结果替换原节点。支持格式见[节点导入](./xray-imports.md)。

### 规则与连接

| 接口 | 用途 |
| --- | --- |
| `GET /rules` | 结构化规则的类型、内容、目标、索引、UUID 及启用状态。 |
| `PATCH /rules/disable` | 用零起始索引设置停用状态，例如 `{"0":true,"1":false}` 停用首条、启用第二条。 |
| `GET /connections` | 活动业务 TCP／UDP 连接、目标、组链、命中规则、字节计数及核心流量总计。 |
| `DELETE /connections/{id}` | 关闭指定业务连接。 |
| `DELETE /connections` | 关闭全部业务连接。 |

规则启停实时应用。App 管理的端口 53 DNS 接管和内部测量路由始终在业务规则之前，模式及默认组切换也保留这些入口。业务连接包含代理与直连目标；健康检查使用独立内部入口。连接源地址是 Xray 到本地转发器的地址，进程字段为空，并非 Android 应用归属信息。

## WebSocket 实时数据

| 路径 | 内容 |
| --- | --- |
| `/traffic` | 每秒推送字节速率 `{"up":rate,"down":rate}`。 |
| `/memory` | 每秒推送核心内存 `{"inuse":bytes,"oslimit":0}`。 |
| `/connections` | 活动业务连接及核心流量总计。 |
| `/logs` | 实时日志 `{"type":"info","payload":"..."}`。 |

日志连接显式指定 `level` 时独立筛选；省略时逐条读取面板保存级别，修改 `log-level` 后已有连接随即采用新值。App 日志页的保存级别与此独立，已保存日志在核心停止后保留。

主核心固定输出 Debug，供各消费端独立筛选；降低保存级别不会降低核心生成日志的开销。改变日志级别或打开、关闭、重连日志流不会重载核心。访问／DNS 日志类别开关在下次核心启动时生效。面板日志会整理重复时间戳和内部连接编号，过滤内部 SOCKS 健康检查的立即关闭提示；采集阶段过滤固定的 Shadowsocks 弃用提示，其余警告和错误保留原等级。

## App 页面、迁移与运行边界

- **配置**管理本地／订阅来源和所属节点；加号菜单提供剪贴板导入、文件导入、手动添加节点和新建分组，更多菜单提供分组管理、重命名／订阅设置及更新全部订阅。
- **代理 → 组设置**管理手选、主备、自动测速策略、成员引用、前置代理和默认组；**设置 → 规则**管理结构化规则及规则资源。
- 不提供完整配置或 Lua 编辑器。旧配置与支持的 Lua 规则模式在首次初始化时迁移，不作为可执行脚本入口。旧路由别名目标只迁移一次；当前目标仍为组、节点或内置目标，重命名会维护相关规则引用。
- 规则、模式和默认组通过路由 API 应用；节点或转发拓扑变化可能重载核心。DNS 保存会重载；入站 `routeOnly` 修改需重启核心，而非仅新建一条连接。

完整页面说明及 DNS 设置见[配置与运行行为](./configuration_CN.md)，目标解析与迁移见[流量规则](./rules.md)。

## 主备回落与恢复

正常使用主节点时，主备组不主动定时轮询主节点；自动测速组仍按自己的计划测量。响应超时或连接失败先复核连通性，再判定节点故障。空闲或目标响应慢本身不等于节点失效，较新的成功测活与真实回复优先于过期失败结果。

每次进入回落后，备用节点首次返回真实数据才启动一次恢复计时；后续回复不反复推迟截止时间。仍需恢复时按配置间隔继续检查主分支。恢复影响新连接，不强行关闭或搬迁已有正常备用连接，包括 TLS 流。已失效的加密流需要应用重新建连；测活正常不保证每个业务目标可达。显式连接删除接口仍按请求关闭指定或全部业务连接。
