# 配置与运行流程

**[English](./configuration.md)** | **中文**

应用将全局配置、节点组和规则分别管理。运行时先组合工作区与全局配置，再执行一次偏好适配，最后注入统计、规则 API 和业务转发入口。最终 JSON 通过 stdin 传给 Xray。

## 存储与编辑

- `global_config.json` 保存 DNS、入站、日志与全局参数。
- 节点组工作区保存 Xray 原生节点、逐节点 `targetStrategy`、成员顺序、主备参数和订阅来源。
- `rules_workspace.json` 保存规则顺序、类型、匹配内容、目标和启用状态。
- 旧 Lua 在首次加载规则时迁移为结构化规则。运行配置采用 Xray JSON。
- 用户编辑过的订阅节点保留编辑结果；其余节点随订阅刷新。
- 配置页新建基本或订阅分组；订阅组保存后自动拉取节点。每组分别提供“编辑节点”“分组设置”与订阅更新入口。分组设置集中编辑来源、运行方式、主节点、备用顺序、测活、恢复、链式代理与默认组；高级路由别名折叠显示。
- 节点子页的加号负责剪贴板、文件导入和手动添加节点，节点提供编辑与删除。页面直接使用路由传入的分组标签。
- 设置的 DNS 分类通过选项编辑 `queryStrategy`、服务器和 hosts；入站分类提供 SOCKS、HTTP 与 `routeOnly`，规则在规则页编辑。日志拥有独立分类，局域网绕过位于 TUN。
- 分组链式代理使用 `frontProxy` 保存前置节点或组，运行时转换为组内节点的 `streamSettings.sockopt.dialerProxy`。链路为本机 → 前置代理 → 组内节点 → 目标。

## 原生页面与编辑

主导航依次为仪表盘、代理、配置、日志、设置。配置页集中展示节点组与规则管理入口；节点、分组设置和规则子页均保持配置导航选中。

代理页专注运行操作，全部分组以圆角卡片展示，初始全部收起。卡片展示组名、选中成员与实际叶节点，右侧为 `Selector`、`Fallback`、`URLTest` 和展开图标。展开后选择成员、查看实际 HTTP 延迟并测量整组；顶部提供搜索、全部展开、全部收起与测速。顶部测速使用当前选中组或首组，沿用单个测量任务。停止运行时主备组显示首个主成员，手动与测速组显示保存的选择；已有延迟值表示历史测量。

节点表单覆盖 VLESS、VMess、Trojan、Shadowsocks、SOCKS、HTTP 六种协议，提供服务器、认证、目标 DNS 策略、TCP/raw、WebSocket、gRPC、XHTTP/SplitHTTP、HTTPUpgrade、TLS 和适用协议的 REALITY 参数。Shadowsocks 提供原生 UDP、UoT v1/v2、simple-obfs HTTP/TLS 与 Host。表单直接更新原出站对象，保留额外字段、其余服务器与用户条目及高级参数；同时支持平铺 `settings` 与旧式 `vnext`／`servers` 数组结构。高级 JSON 提供完整出站编辑，覆盖表单列表以外的已导入原生协议。

规则子页沿用结构化编辑，维护规则类型、匹配内容、出站目标、启用状态、拖动或上下移动排序，以及导入和 JSON 导出。YAML 用于配置与订阅导入，规则编辑使用现有结构化控件。导入校验随入口而定，详见[原生节点导入](./xray-imports.md)。默认组在配置 → 分组设置中指定，提供全局模式与兜底出口，专门规则继续使用自己的目标。

## TUN

| 模式 | 行为 |
| --- | --- |
| Xray TUN | 保留或注入 `tun` inbound，传入 Android VPN 描述符。 |
| Hev TUN | 使用原版 Hev 引擎，经本地 SOCKS 入站接入 Xray。 |
| Simple TUN | 使用原版 SimpleTUN 引擎，采用 IPv4 与 `noauth` SOCKS 入站。 |

Xray TUN 的 MTU、接口名称和嗅探参数根据应用设置补齐。Hev 与 Simple TUN 模式移除配置中的桌面 TUN 入站。

TUN DNS 由 App 自动管理，界面只维护全局 DNS／DoH 上游。Android VPN 登记内部接收地址 `198.18.0.2`，启用 IPv6 的 Hev／Xray TUN 同时登记 `fc00::2`；这些地址仅用于接收系统查询。显式主机路由确保接收地址走 VPN，包括开启局域网绕过时的 IPv6 查询。

解析流程为：应用 DNS 请求 → TUN → Xray 全局 DNS／DoH → 返回解析结果；随后业务连接按规则出站。应用入口的 UDP／TCP 53 查询优先进入原生 DNS 出站，核心上游请求和内部节点转发使用各自入口，避免循环。规则编辑与分流模式切换继续保留这条接管规则。应用自带的加密 DoH／DoT 沿用应用指定的解析服务。

全局服务器列表启用 Xray 原生 `enableParallelQuery`。所有被当前域名策略选中的上游同时查询，相邻且策略相同的上游采用最先成功的有效地址结果，后续策略组在前组全部失败后接替。`domains`、`skipFallback`、`finalQuery` 和结果筛选规则继续生效；为同一类域名配置多个相同策略的上游即可并发容错。已有 DNS 脚本继续负责自身调度。

原生 DNS 出站将 A／AAAA 地址查询交给全局解析，其余记录类型按核心默认策略返回成功空应答。DoH 引导 DNS 仅解析 DoH 服务器域名，独立于日常查询的并发组。

## 全局适配

| 字段 | 处理 |
| --- | --- |
| `geodata` | 资源更新交由应用管理。 |
| `log.error` | 核心日志输出到应用读取的进程流。 |
| `log.access` | 关闭访问日志时设为 `none`。 |
| `log.dnsLog` | 跟随应用 DNS 日志设置。 |
| `log.loglevel` | 主核心启动时固定为 `debug`，整个会话保持该级别，独立于 App 与面板级别；App 的 Auto 读取全局配置作为保存阈值，缺省 `warning`。 |
| 主 SOCKS 入站 | 同步应用地址、端口和认证设置。 |
| 其他通配监听地址 | 改为 `127.0.0.1`。 |
| `dns.hosts` | 按现有逻辑补齐阿里 DoH 域名的静态地址。 |
| `dns.enableParallelQuery` | 标准服务器配置运行时设为 `true`；DNS 脚本保留自身调度。 |
| 域名形式的 DoH | 设置 → DNS → DoH 引导 DNS 提供地址选项，默认 `223.5.5.5`。运行配置为 DoH 域名添加精确匹配，通过所选 IP 的 TCP 53 端口直连解析。地址独立保存在 App 偏好中，保存后应用到运行核心，临时测速共用该设置。原有 hosts 和指向独立解析器的显式终结规则优先生效。 |
| TCP 出站 socket 参数 | 沿用原有保活和超时注入逻辑，保留用户显式配置。 |

## 分流与主备

所有业务目标均进入共享本地转发入口，覆盖节点组、物理节点、直连和拒绝目标。业务连接采用节点保存的 `targetStrategy`。手动测速、定时测活和主节点恢复检查走独立入口，选择 `targetStrategy: AsIs` 的测速专用出站，继续沿用节点传输、服务器地址解析、链式代理和 simple-obfs 设置。

主节点健康期间保持业务连接，周期任务跳过主节点。新连接建连失败或首响应超时后尝试备用；备用交付首个响应后开始恢复计时，到期单独检查主节点。恢复成功后新连接使用主节点。备用 URL-test 组按自身检查间隔和结果信任时长运行。

组会话准备完成后立即公布核心连接就绪，首轮 URL-test 测活随后在后台异步执行。转发入口为候选等待首轮测量结果时，仍以该组超时为上限。启用的本地 API 在服务启动阶段、首轮测活之前启动，API、核心就绪与各节点测量结果分别表示各自状态。后续测活会预留 HTTP 请求时间，在已知结果的信任期限到达前启动下一轮。单成员测速组同样按测速策略运行；嵌套主备组按各分支独立选择候选。

HTTP 延迟通过所选节点连续发送两次 HEAD。首次完成连接准备，第二次测量请求发送到响应头返回的实际往返。每次测量拥有独立连接池，各节点拥有独立调度器；超时覆盖连接准备和两次请求。原生界面、定时测活、独立测速和 zashboard 共用该结果。

分组回调沿响应节点所属的当前选中分支更新。已连接备用保持优先，新连接失败后释放选择；恢复判定与连接回调共用状态锁，测活结果尊重开始测量之后收到的失败。TCP 建连与首响应期限沿用现有流程：客户端载荷到达后开始首响应等待，首段重放保留至多 256 KiB。

对启用响应观察的已建立 TCP 流，业务上传按分组超时等待响应；下行进展清除等待，仍在写入的 socket 继续保留确认机会。到期后通过该叶节点的 AsIs 入口执行真实 HTTP 确认，确认自身以同一个组超时为上限。有效失败结果关闭对应挂起流；组状态更新额外要求选择路径和测量状态仍有效。其他流已触发切换时，旧流仍可在独立确认后结束；更新的健康结果优先。确认健康时保留连接，持续阻塞的写入继续安排限时确认，空闲连接保持被动。UDP 沿用首响应期限与实际传输错误的回落判断。

首轮测活期间，自动测速组优先选择已有健康结果的成员，其余待测成员按配置顺序尝试，各次尝试继续遵循建连和首响应期限。测量完成后沿用延迟排序和结果有效期。

已有加密流切换出口需要应用重新建连，原连接仍绑定原传输端点。特定目标被封锁时，测活地址仍可能正常响应；恢复效果取决于测活路径和应用重连行为。备用实际返回数据后启动主节点恢复计时，恢复成功后后续连接使用主节点。

设置默认组时，最后一条启用的 `Match` 规则同步改为 `GLOBAL`，由默认组提供兜底出口。域名、IP 与其他专门规则继续使用各自的目标。原生界面与 zashboard 的 GLOBAL 切换共用此行为。

参考 `h3.yaml` 的结构，顶层手动组可以选择主备组，主备组以 CF 或 AWS 为主节点、以多个订阅测速组为备用。物理节点各自保留 `targetStrategy`：CF 的 `UseIPv4` 在本地解析目标，AWS 的 `AsIs` 将域名交给远端。共享转发入口使用 `AsIs` 保留域名，最终由选中节点执行解析策略。

规则编辑、规则启停和模式切换通过 Xray API 应用。节点内容与组拓扑变化触发核心重启。

## API 与统计

运行时启用 `StatsService`、`RoutingService` 和 `HandlerService`。核心统计包含物理节点与 UoT 出站流量，排除内部业务转发的重复计数。Clash API 将业务连接、命中规则、日志、流量与内存转换为 zashboard 格式。

连接源地址反映本地转发入口，进程字段保留为空。原生主入口为仪表盘、代理、配置、日志与设置；分组节点、分组设置与规则管理位于配置子页，实时连接在 zashboard 查看。

启用的 Clash API 在服务启动阶段、首轮组测活之前启动。组会话准备完成后立即发布核心就绪，首轮整批测活在后台执行。服务正在启动或运行时，开关、端口与密钥更新仅重启 API 监听器，Xray 核心和业务流继续运行；服务停止时保存设置，供下次启动使用。

设置页通过 `ZashboardLauncher` 打开面板，点击时读取当前地址、端口与密钥，并通过浏览器片段传给面板；本地 API 沿用 Bearer／WebSocket token 鉴权。密钥读写与重置串行执行，并发首次读取采用同一生成值。API 设置实时应用与打开面板分别执行各自流程。

同一核心原始日志流供 App 保存与 zashboard 独立筛选。日志页顶部选择 App 保存级别，仅写入 SharedPreferences 并更新选择器，控制后续文件写入和保存日志界面新增条目；Warning 保存警告和错误，None 暂停保存。面板级别独立保存，初始 `error`。显式 `/logs?level=debug` 按 Debug 筛选该连接，优先于面板保存级别；省略 `level` 时逐条读取 `ClashApiPreferences.logLevel`，`PATCH /configs` 的 `log-level` 更新直接影响已连接的默认订阅。

App、面板级别调整与日志订阅打开、关闭、重连均产生零 `GlobalConfigStore.notifyModified` 调用和零核心重载。App Warning 下核心详细日志生成仍消耗 CPU 与管道传输资源；逐行 `XrayLog` Logcat 回显已移除。Access、DNS 类别开关在下次核心启动时生效，本地保存同时遵循 App 级别；原有路由与 DNS 配置重载行为继续保留。

已保存日志在核心启停后继续保留，沿用现有文件容量限制，日志页支持搜索、导出和主动清空。采集时过滤 Shadowsocks 的固定弃用提示，实际连接警告和错误继续保留；历史已保存记录继续可见。

仪表盘状态主卡片展示服务状态、国家代码、出口 IP、地区与直连／代理标签、运行时长和网络机构，出口数据来自 ipwho.is。运行连接时使用专用 HTTP 入口，强制经过当前默认出口；停止时查询直连出口。页面打开、连接与出口切换时更新，手动刷新图标位于状态主卡片内，保持零定时查询。

仪表盘保留出站模式、综合状态、网络速度和内存四张卡片。zashboard 从设置分类进入；运行节点选择位于代理页，节点管理与默认组设置位于配置的分组子页。内存继续显示应用与核心的 RSS 分项、合计和占比，沿用可见页面刷新及共享页计量方式。

全局 DNS／DoH 上游集中在设置 → DNS → 服务器，支持添加多项并发解析。DNS 页面保留可编辑的解析策略、引导地址、服务器和 hosts；TUN 页面移除静态 DNS 说明行。

## APK 更新

Groups 工作流从 Actions Secrets 读取固定签名密钥，版本号随构建序号递增。包名为 `com.fallback.xm`，调试和发布构建使用同一应用身份。旧包名版本与此包独立安装，之后的同包名固定签名版本可以覆盖更新。

`routeOnly` 默认 `false`，对运行时 SOCKS、HTTP 与 Xray TUN 入站统一应用。开启时嗅探结果用于路由，关闭时同时更新连接目标；入站选项保存后在下次连接时应用。

代理页手动测延迟使用实际 HTTP 往返。连接关闭时临时启动 Xray 测量会话，目标解析统一为 AsIs，沿用节点链式代理设置，完成后结束进程。运行连接时使用现有核心的测量入口。界面区分待测、测量中、延迟值和失败。
