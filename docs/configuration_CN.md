# 配置与运行行为

**[English](./configuration.md)** | **中文**

LucX 分别管理全局设置、节点组和流量规则。启动时组合三者，应用 Android 偏好，再加入内部路由与统计入口。最终 Xray JSON 通过 stdin（`-config stdin:`）传入核心。

## 页面

| 页面 | 用途 |
| --- | --- |
| 仪表盘 | 启停服务，选择规则／全局／直连模式，查看状态、出口信息、速度和内存。 |
| 代理 | 选择组成员、测量 HTTP 延迟，以及打开代理组运行设置。 |
| 配置 | 管理本地／订阅来源及其所属节点。 |
| 日志 | 搜索、导出或清空已保存日志，选择 App 保存级别与访问／DNS 日志选项。 |
| 设置 | 通用、TUN、入站、规则、DNS、面板和关于。 |

### 配置：来源与节点

通过分组标签和左右滑动切换当前分组；浏览位置与默认路由组相互独立。加号菜单提供**从剪贴板导入**、**从文件导入**、**手动添加节点**和**新建分组**。更多菜单提供**分组管理**，本地组显示**重命名分组**，订阅组显示**订阅设置**；存在订阅时另有**更新全部订阅**。长按标签可修改名称或订阅链接。分组信息栏提供测速，订阅组另有刷新入口。

节点列表显示该组实际拥有的节点，而非代理策略引用的全部成员。点击节点进入编辑，节点菜单提供复制与删除。导入只向当前组添加节点，不替换全局 DNS、入站或流量规则。参见[支持的导入格式](./xray-imports.md)。

### 代理：运行组设置

卡片初始收起，展示策略、选中成员，以及运行时的实际叶节点。展开后可选择成员、测量整组，或打开**组设置**。顶部提供搜索与全部展开／收起。

组设置负责手动选择、主备回落、自动测速策略，成员引用与顺序，测活地址／时间参数，前置代理，以及**保存并设为默认组**。成员可以是节点、其他组、`direct` 或 `block`；显式成员列表留空时使用本组所属节点。前置代理的链路为本机 → 前置代理 → 本组节点 → 目标。

手选组在停止时也能保存选择；自动组可在运行时临时切换成员。历史延迟不能证明节点当前已连接。停止服务后也能测速，此时使用临时 Xray 会话。

`GLOBAL` 使用选定的默认组，`DIRECT`／`direct` 和 `REJECT`／`block` 仍是内置目标。设置默认组时，最后一条启用的 `Match` 规则也会指向 `GLOBAL`，专门规则的目标不变。目标解析、重命名与数据迁移详见[流量规则](./rules.md)。

### 主备回落与恢复

LucX 与 CMA、FlClash 共用以下回落约定。LucX 由 Kotlin 中继观察流量，由分组控制器选择路由。

- 正常主节点依靠真实业务反馈识别故障，自动测速组继续使用独立测量计划。
- TCP 和 UDP 按候选顺序通过本地 SOCKS 接入 Xray，最多尝试 3 个候选；分组设置限定本地连接建立时间。SOCKS 应答表示本地入口已接收请求，本地 SOCKS 故障由本地处理，远端健康状态依据真实业务和测活结果判断。
- 每次 TCP 写入都有独立的 4–10 秒阻塞窗口。等待回包时，完成写入可顺延响应期限，最迟为首笔待应答写入起的两个窗口。若期限届满时上传仍在持续写入，缺少回包仅是弱信号：该目标的下一条连接可改走备用成员，当前上传继续使用原连接。
- 空闲窗口到期后，若 TCP 流收到对端推送，随后一个窗口内的首笔写入既可能是对推送的应答，也可能是新请求。此后若无回包，同样只将其作为调整该目标后续选路的弱信号，当前连接保持打开。若写入阻塞超时、发生明确的 I/O 故障、发送端静默后真实请求仍未收到应答，或独立测活确认成员失效，中继仍按原有规则清理连接。
- TCP 响应停滞、仍有请求待应答时收到普通 EOF（即使先前已有回包）、强 I/O 错误或 UDP 回包超时，都可让该目标在接下来 60 秒内为新连接优先尝试其他成员。匹配的回包清理对应成员和目标的记录。按目标排序仅调整代理成员之间的顺序，`direct`、`block` 保留在分组常规顺序中的原位。其他目标沿用原有路由。
- 界面显示分组默认首选，单个目标此时可能已走备用。整组降权要求 60 秒内有 3 个独立目标出现强失败，或本成员测活失败而另一成员成功。等待回包时收到普通 EOF、UDP 回包超时，对整组均为弱信号。
- 多个目标共用本地 UDP 端点时，每个目标单独选择回落上游。只要 SOCKS 控制连接仍在，健康目标便保留自己的通道，空闲时也一样。某个目标等待回包超时后可单独切换成员，其余目标继续使用各自的通道。仅当回包可唯一对应到某个目标时，才清除该目标的待应答记录；域名请求收到 IP 回包时也遵循此规则。
- 强、弱复核分别以 3 秒和 15 秒为最短间隔合并调度。嵌套分组先评估子组候选，再向上层评估；取得并发名额后开始计算测活超时。
- 失败状态归属当前代理实例与路由。同一路由以较新的真实回包为准，即使先前发起的测活随后才返回失败结果。降权冷却从 30 秒依次增加至 60、120、240 秒，最长 300 秒。冷却期间保留原有截止时间，迟到回复同样保留冷却；冷却结束并稳定 5 分钟后的真实回复会降低一级退避。候选依次排列为冷却期外健康成员、冷却期内健康成员、冷却期外其他成员、剩余成员。手动选择会清理该成员的失败状态。
- 选中备用成员后启动配置的主节点恢复间隔，健康结果排序导致的切换同样启动恢复计时。恢复检查处理冷却已结束的成员，成功后由新连接使用恢复成员。
- 首个回包前，若首批数据总量在 256 KiB 以内，中继可完整重放这批数据，最多尝试三个候选。选中可用替代路径后仅替换上游套接字，即使祖先组仍在测活，也可保留本地客户端连接。路径失效后，已建立的 TCP/TLS 连接由应用重连。
- 每段连续空闲期仅触发一次弱测活信号。空闲窗口到期后，若实际承载会话的成员已确认失效或已降权，且两秒采样期间仍无进度，才可清理该空闲会话。常规首选变更、主节点恢复和手动切换均保留健康空闲会话的原连接；仍有进度的传输也继续使用原连接。实际回落耗时包含适用的响应窗口、对照测活和清理时间。

## 存储与编辑

| 存储 | 内容 |
| --- | --- |
| `global_config.json` | DNS、入站、日志及其他 Xray 全局参数。 |
| `groups_workspace.json` | 节点出站、来源链接、策略、有序成员引用、前置代理和默认组。 |
| `rules_workspace.json` | 带 ID、类型、匹配内容、目标与启用状态的有序结构化规则。 |

节点表单覆盖 VLESS、VMess、Trojan、Shadowsocks、SOCKS、HTTP，提供认证、`targetStrategy`、传输和适用的 TLS／REALITY 设置。Shadowsocks 另有原生 UDP、UoT v1/v2 和 simple-obfs HTTP/TLS。表单修改原始出站并保留额外字段；**高级 JSON** 编辑完整节点出站，也用于其他支持的原生协议，而非整份运行配置。

设置 → 规则提供结构化编辑、启停、拖动或上下排序，以及 JSON 导入／导出。**规则资源**打开 `.dat` 资源管理页。规则导入会替换规则列表，与节点导入相互独立。

当前 UI 不提供完整配置或 Lua 编辑器。首次初始化时可从已有旧数据恢复全局设置、节点、分组及支持的规则；删除编辑页面并不删除这些数据。旧 Lua 处理仅一次性转换支持的规则模式，不执行任意脚本；迁移后请检查提示和结构化规则列表。

## DNS 与嗅探

设置 → DNS 依次显示**解析策略 · queryStrategy**（`UseIP`、`UseIPv4`、`UseIPv6`）、**DoH 引导 DNS**、**全局 DNS**、**分流 DNS 服务器**及**静态映射 · hosts**。全局 DNS 编辑没有域名条件的条目，分流 DNS 编辑 `domains` 非空的条目；两者更新同一份 `dns.servers` 并保留顺序。

服务器表单提供地址（IP／DoH／DoT）、可选端口、解析策略（跟随全局或以上三种策略）、期望 IP（`expectIPs`）及客户端 IP（`clientIp`）。分流服务器另有逐行域名条件和**仅处理匹配域名**（`skipFallback`）开关。hosts 接受域名或匹配表达式，以及一个或多个目标 IP／域名。设置入口的整理不会重置已有服务器或更改已保存的默认值。

新建全局配置采用 `UseIP`，服务器为 `https://1.1.1.1/dns-query` 和 `223.5.5.5`。服务器列表 DNS 配置在运行时启用原生 `enableParallelQuery`，域名筛选与结果过滤仍然生效。DoH 引导地址默认 `223.5.5.5`，为端点域名建立精确匹配，通过直连 TCP 53 解析；已有显式 hosts 和适用的终结引导规则优先。保存 DNS 或引导地址会自动重载运行中的核心。

VPN 登记内部 DNS 接收地址 `198.18.0.2`；Hev／Xray TUN 启用 IPv6 时另有 `fc00::2`。从 TUN、SOCKS、HTTP 客户端入站进入的 TCP／UDP 53 请求，在业务规则之前交给 Xray DNS 出站。A／AAAA 查询使用全局解析器；其他记录类型按核心 DNS 出站默认策略返回成功空应答。应用自带的加密 DoH／DoT 不会转换为这条 53 端口路径。

**入站 → routeOnly** 默认 `false`，统一应用于运行时 SOCKS、HTTP 和 Xray TUN 嗅探：

- 开启：嗅探到的域名用于路由，保留原始连接目标。
- 关闭：嗅探还可将连接目标替换为该域名，再由选中节点的 `targetStrategy` 决定目标解析方式。
- 这不是 DNS 接管开关。修改后必须**重启服务**，仅在原核心中发起新连接不足以生效。
- 运行配置会将 `full:cloudflare-ech.com` 加入 `domainsExcluded`，避免把浏览器 ECH 的公共外层名称误当成网站目标。保留已有排除项、`routeOnly` 和节点 `targetStrategy`，不放宽 TLS 证书校验。

## TUN 与本地入站

| 后端 | 行为 |
| --- | --- |
| Hev Socks5 Tunnel（默认） | 将 VPN 流量转发到本地 SOCKS 入站，支持配置的 IPv6 与 SOCKS 认证选项。 |
| Xray TUN | 将 Android VPN 描述符用于 Xray `tun` 入站，补齐缺失的 MTU、名称和嗅探设置。 |
| SimpleTUN | 使用 IPv4、MTU 1500 和无认证 SOCKS 路径；此后端禁用 IPv6 与 MTU 编辑。 |

主 SOCKS 入站采用 App 地址和端口，仅接受回环 IP；用户名与密码必须同时设置或同时留空。SimpleTUN 会移除主 SOCKS 认证以使用无认证路径。系统 HTTP 代理跟随已有 HTTP 入站的实际端点，无 HTTP 入站时才补充本地入站。非 TUN 入站缺失或通配的监听地址会被限制为回环地址。

绕过局域网同时影响 VPN 路由排除与系统 HTTP 代理的 IPv4 排除列表。自行配置代理的应用仍采用自己的代理策略。修改 TUN、局域网绕过或入站偏好后需重新连接。

## 运行适配与生效方式

| 项目 | 运行行为 |
| --- | --- |
| 规则资源 | App 在规则资源页管理内置／自定义 `.dat`、校验、下载和更新计划，不使用核心 `geodata` 管理。 |
| 日志 | 移除 `log.error`；关闭访问日志时使用 `none`；`dnsLog` 跟随 App 开关。主核心输出 Debug，供各消费端独立筛选。 |
| API／统计 | 配置回环 `StatsService`、`RoutingService`、`HandlerService`、出站上传／下载统计，以及内部业务／测量路由。 |
| TCP 代理传输 | 补齐缺失的保活／超时参数（`tcpKeepAliveIdle=15`、`tcpKeepAliveInterval=3`、`tcpUserTimeout=15000`、`TCP_KEEPCNT=3`），保留显式配置。 |
| 节点测量 | 经 `targetStrategy: AsIs` 的测量出站进行 HTTP HEAD 往返测量，业务出站保留节点保存的策略。 |

规则内容、规则启停、路由模式与默认组通过 Xray 路由 API 应用。节点变化，以及组名、前置代理或转发目标集合变化，会重载核心；DNS 保存也会重载。服务启动中或运行中修改本地控制器的开关、端口或密钥，只重启该监听器；停止时则保存供下次启动使用。

App 日志级别立即影响后续保存条目，不重载核心。`Auto` 读取全局日志级别，缺省为 `warning`；`None` 暂停保存。已保存日志在服务停止后保留。面板日志级别独立，默认 `error`；显式 `/logs?level=...` 优先决定该连接的筛选级别。访问／DNS 日志开关在下一次核心启动时生效。降低保存级别不会停止核心生成 Debug 日志。

## 内置 zashboard

APK 包含 **zashboard v3.30.0**。开启设置 → 面板中的控制器，启动服务并等待连接成功，再选择**打开内置 zashboard**。地址为 `http://127.0.0.1:<port>/ui/`，默认端口 `9090`，`/` 会重定向到该路径。静态页面无需 API 鉴权，HTTP／WebSocket 控制操作仍需要密钥。

App 入口通过浏览器片段传递后端参数与密钥。若手动输入本地网址，首次需配置后端 `http://127.0.0.1:<port>`，并粘贴从面板页复制的密钥。修改端口或密钥后，可从 App 重新打开，或更新已保存的后端。HTML、脚本和样式随 APK 打包，不依赖外部托管网页或联网下载。控制器开启且随服务运行时才提供本地页面，实时统计和控制还需要运行中的核心。参见 [Clash API](./clash-api.md)。
